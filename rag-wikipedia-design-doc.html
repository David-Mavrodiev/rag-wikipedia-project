RAG System over Wikipedia

An end-to-end Retrieval-Augmented Generation system that answers natural-language questions over a Wikipedia subset with grounded, cited answers, served by a self-hosted open-source LLM.

01Problem & context

Large knowledge bases like Wikipedia contain answers to a vast range of questions, but finding and synthesizing them means manually searching and reading across many articles. A general-purpose LLM can answer from parametric memory alone, but its answers are unattributable and prone to hallucination.

This project builds a RAG system over a Wikipedia subset: it ingests a real corpus, indexes it for semantic search, and answers natural-language questions with cited sources using a self-hosted open-source LLM. Answers are grounded in retrieved passages and attributable back to their source articles. The system is delivered as a set of incremental, independently demoable phases, each with tests.

Data pipeline

A batch ingestion pipeline (download → clean → chunk → embed → load) orchestrated with Prefect, writing to a dedicated vector database (Qdrant).

Application & services

A clean, testable Python service (FastAPI) and a React web app, containerized with Docker Compose, with tests, config, and documentation.

Retrieval & generation

Embeddings, vector retrieval, prompt construction, a self-hosted LLM (Ollama), and a rigorous evaluation harness.

02Goals

  • Answer questions over a Wikipedia subset, returning answers with source citations.
  • An idempotent, re-runnable Prefect ingestion pipeline: download → clean → chunk → embed → upsert.
  • A dedicated vector DB (Qdrant) in Docker for retrieval.
  • A self-hosted open-source LLM via Ollama (llama3.2:3b) behind a swappable interface.
  • A FastAPI backend and a React web app showing answers and cited sources.
  • A RAG evaluation harness: golden Q&A set + retrieval metrics + answer groundedness metrics.
  • Everything packaged with Docker Compose to run locally in a few commands.
  • Shipped as phased milestones, each independently demoable, with tests.
  • A clear README + runbook for reproducibility.

03Non-goals

  • Training or fine-tuning an LLM from scratch (a possible future spin-off).
  • Production-grade multi-tenant auth, billing, or user accounts.
  • Cloud / Kubernetes deployment, autoscaling, or HA (local Docker Compose is the target).
  • Real-time / streaming ingestion (the pipeline is batch).
  • Indexing the entire Wikipedia dump — a bounded subset is used (tiny ~500 / real ~25k articles).
  • Hybrid search (BM25 + vector) and reranking — these are stretch goals, not v1.
  • GPU optimization / large-model serving performance tuning.

06Users & scenarios

Ask a question

User types a question → frontend calls POST /query → backend embeds, searches Qdrant, assembles a grounded prompt, calls the LLM → returns answer plus citations, rendered with expandable sources.

(Re)build the index

Operator triggers the Prefect flow → download, clean, chunk, embed, upsert into Qdrant. Idempotent — re-running does not duplicate data and can resume.

Evaluate quality

Operator runs the eval harness against the golden Q&A set → retrieval metrics (recall@k, MRR) + answer groundedness, as a comparable report.

Edge & failure cases

  • No relevant context found → the system says it doesn't know rather than hallucinate.
  • Ollama / Qdrant unavailable → clear error; health check fails fast; graceful UI message.
  • Empty / oversized / non-English query → validated and handled.
  • Partial ingestion failure → pipeline resumes without duplicating data.
  • Very long retrieved context → truncation / token-budget management.

07Acceptance criteria

  • docker compose up brings up all services healthy on a clean machine following the README.
  • The Prefect ingestion flow runs end-to-end and populates a Qdrant collection with vectors + source metadata.
  • Re-running ingestion is idempotent (no duplicate vectors; resumable after interruption).
  • POST /query returns a grounded answer with citations for known-answerable questions.
  • When no relevant context is found, the system declines instead of fabricating an answer.
  • The React web app lets a user ask a question and view the answer plus expandable cited sources.
  • The LLM and embedding model are each swappable via configuration.
  • The evaluation harness outputs retrieval metrics (recall@k, MRR) and answer groundedness metrics.
  • Unit tests cover core logic; integration tests cover the query path; tests pass locally.
  • A README + runbook documents setup, ingestion, querying, and evaluation.

08Testing strategy

Unit (pytest)

Cleaning/normalization, chunking, prompt assembly, citation formatting, config parsing, mocked LLM/embedding adapters.

Integration

Qdrant + mocked/small LLM exercise the ingestion → retrieval → answer path on a tiny fixture corpus.

Pipeline

Prefect flow on a fixture subset; assert idempotency (re-run = same count) and resumability.

Evaluation

Golden Q&A set as a quality regression: recall@k / MRR for retrieval, groundedness for answers.

09Phased roadmap

Strictly sequential — each phase ships a working, demoable slice with tests. The tiny dev profile is used throughout for fast iteration; the real profile is a final pass.

1

Scaffolding & infra

Repo skeleton; Docker Compose with Qdrant + Ollama healthy; FastAPI GET /health; config, logging, test harness.

uv initdocker-compose/health

Done when: docker compose up → /health green; make test passes.

2

Ingestion pipeline (Prefect)

Idempotent flow: download → clean → chunk → embed → upsert. Deterministic point IDs for idempotency.

sourceschunkingembeddingsvectorstore

Done when: make ingest PROFILE=tiny populates Qdrant; re-run is a no-op.

3

Retrieval layer

Embed query → Qdrant top-k → map to source metadata → token-budget context assembly (vector-only for v1).

retrievaltop-k

Done when: retrieval returns relevant chunks for known questions.

4

Generation

Grounded prompt + citation markers; Ollama call; refusal when context is weak; citation extraction.

promptllmcitations

Done when: grounded, cited answer is produced; no-context yields a refusal.

5

API

POST /query → {answer, citations[]}; pydantic models; input validation; error mapping when deps are down.

/queryvalidationerrors

Done when: curl POST /query returns grounded answer + citations.

6

Web app (React)

Minimal Vite+TS app: ask a question, see the answer + expandable citations; loading/error states.

Curate golden.jsonl; retrieval metrics (recall@k, MRR); answer groundedness (optional LLM-as-judge); saved report.

Finalize Compose wiring + healthchecks; README quickstart; runbook; tidy Makefile targets.

Stretch goals (only after Phase 8): hybrid retrieval (BM25 + vector), a cross-encoder reranker, answer streaming to the web app, and cloud VM deployment.

10Risks & mitigations

RiskMitigation
Scope is largeStrict phasing; each phase ships a demoable slice; stretch items fenced off.
Local compute limitsTiny dev profile + small CPU-friendly models + batched embeddings.
RAG quality is hard to judge subjectivelyEvaluation harness provides objective, repeatable metrics from early on.
Multi-service setup frictionDocker Compose + documented runbook; per-service health checks.
Hallucination / ungrounded answersEnforce grounding in the prompt, return citations, implement a "don't know" path, measure groundedness.
Index / embedding dimension mismatchDerive dim (384) from the model; assert against the Qdrant collection at startup.

11Open items

  • Final chunking parameters (token size / overlap) — tune after the first eval run.
